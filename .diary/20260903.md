
## 17:21 2026-09-03


Picked up the risk-defect work after the subagent hit its session limit
mid-fix, and finished the list myself.

**Fixed (each with a test that fails before it):**
- `release_frozen_for_order` removed the freeze entry and then returned on an
  owner mismatch, so the primary map lost it while `frozen_by_user` still
  counted it — permanently over-reserving the true owner's margin. Now takes
  the entry and only removes on match, logging the impossible state loudly.
- `process_fill` mutated the taker/maker position and then returned on a
  missing account, leaving the tip unadvanced so replay double-counted (#4).
  `ensure_*` runs immediately above, so a miss is a programming error: panic
  with a named invariant instead of corrupting money quietly.
- **Socialized loss** — founder's call: re-triggering is intended (the
  exchange keeps drawing until the position is covered), but the ~5.5 s
  cascade cadence was wrong. Added a per (user, symbol) cooldown, default
  2 min via `RSX_LIQUIDATION_SOCIALIZED_COOLDOWN_NS`.
- `max_leverage` was stored, settable, logged and **never read** — the cap
  shown in the new Config tab meant nothing, only the margin rate's implied
  cap applied. Enforced against gross portfolio notional.
- Unparseable `RSX_SYMBOL_*` overrides were silently ignored, leaving the
  shard on its default. Now loud; the five copy-pasted blocks became one loop.
- Warm standby never checked the shutdown flag (SIGKILL-only). Checks each
  pass, and the promotion after it is guarded so a shutting-down node never
  becomes the writer.
- `maybe_process` allocated two `Vec`s per busy-spin pass; returns before
  allocating when nothing is liquidating.
- Dead code gone: `MarkPriceUpdate`, `is_acquired`. `rand_jitter` existed
  twice with different moduli — one copy in `risk_utils`.

**Database ownership** (founder's call): risk owns Postgres and runs all
migrations. The symbol catalog moved to `rsx-risk/migrations/005,006` and
`rsx-matching/src/schema.rs` is gone — the ME is a reader again. Migration
ids stay `001_symbol_config`/`002_seed_symbols` because they are already
recorded in deployed `migrations` tables and the DDL is not re-runnable.
Verified by dropping the tables *and* their migration rows and restarting:
risk recorded both ids and restored all 8 symbols, no manual psql. That was
the real complaint — the earlier hand-applied `psql -f` was papering over the
fact that nothing ran these at boot.
