## 21:30 — rsx-risk step: config from Postgres, split landed, docs rewritten

Finished `.ship/53` step 1 on top of the three split commits.

**Config (a3a28bf7).** Margin rates, leverage cap and fees now come from the
active `symbol_config_schedule` row per symbol — the same query the playground
Config tab runs. The hardcoded 10%/5%/10x loop and the `RSX_SYMBOL_<id>_*` env
overrides are gone; `ShardConfig::symbol_params` is `Vec<Option<_>>` and an
unconfigured symbol rejects orders with `SymbolNotConfigured`
(`SymbolNotFound` on the wire) rather than trading on an invented default.
One apply path (`apply_symbol_config`) serves boot, promotion and live reload.
Live reload stays off the pinned core: `CONFIG_APPLIED` newer than the applied
version pushes `PersistEvent::ConfigReload`, the persist sidecar reads that
exact version and hands it back over a 64-slot config ring that `tick` drains
first. A warm node has no sidecar, so promotion reloads every symbol before the
first live order. `symbol_config_test` (testcontainers) pins the seed, the
effective-date cut-off and the sidecar round-trip.

**Replay-from-WAL decision.** Deleted. Risk writes no WAL, so the boot step
read an empty directory in every deployment; the ME replication stream is the
one recovery source (warm catch-up and gap drain both go through
`apply_record`). The tests that fed hand-written segments into a shard do it
through `tests/common::replay_wal_dir`.

**Deviations from the .ship/51 table.** No `me_receiver.rs` — `MeReceiverState`
is a private field of `cast_loop::CastIo`, a 5-line struct does not earn a
module. `failover.rs` went away instead of shrinking: `handle_replay` and
`apply_me_replay_record` are replay, `forward_to_gw` is egress (`rings.rs`),
and the warm-catchup protocol is `promotion.rs`. `db.rs` moved into the lib so
the persist worker can open its own connection.

**Behaviour changes beyond the plan, all small:** malformed env values
(`RSX_RISK_SHARD_ID=abc`, a bad `RSX_RISK_CORE_ID`) fail the boot instead of
silently defaulting; the gateway/mark replication endpoints are read once at
boot and an unset one skips the gap (the gateway's own precedent) instead of
panicking at fault time; risk-originated rejects carry a nanosecond timestamp.

**Spec check.** 28/13/42/6/19 now describe the warm-standby protocol, the
module layout, the Postgres config source and the real table names. Four gaps
needed a design beyond the spec and went to BUGS.md as proposals: funding
settles one interval on every boot (no persisted interval id), funding config
is global while the schema is per symbol, liquidation entry does not cancel
open orders (no cancel egress, no symbol_id in the freeze entry), and the
post-max-rounds socialization amount disagrees with 13-liquidator.md §9.

this crate's convention (repo CLAUDE.md: comments state current behaviour or a
load-bearing invariant) keeps the invariant comments. Removed only the history

adjacent log lines. Flagging it rather than silently following either rule.
